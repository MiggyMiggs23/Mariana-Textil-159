# Clasificación de las 130 referencias de restricciones por rol

**Corte:** las referencias `R001`–`R130` son exactamente, y en el mismo orden,
las 130 filas de referencia de `docs/remaining-role-checks.md` al hacer esta
clasificación. Este documento no reaudita líneas nuevas ni cambia el runtime.
No se modificó código, no se consultó la base de datos y no se ejecutaron
workflows, la aplicación o pruebas.

## Regla de clasificación

Cada referencia tiene **una sola categoría primaria**. Una fila mixta conserva
en `secundaria` sus otras cláusulas, para no convertir un scope territorial en
una justificación de veto de acción ni una redacción en un veto.

* **N1 — territorial legítima (32 referencias):** el rol fuerza, selecciona,
  lee o muta el sitio que le corresponde. Es una restricción de ubicación que
  debe conservarse. Si una referencia también contiene un veto de acción,
  se clasifica en N3 y conserva el alcance legítimo como cláusula secundaria.
* **N2 — ocultamiento sensible legítimo (13 referencias):** se ocultan,
  eliminan o no se entregan costos, precios, margen, crédito, pagos u otros
  datos financieros/sensibles por rol. No implica que la acción de negocio
  esté prohibida.
* **N3 — veto de acción para revisión (69 referencias):** un guard literal de
  rol, allowlist o guard frontend bloquea una acción aunque pueda existir un
  permiso de matriz. Se indica si es **server-side**, **UI-only**, o si el
  servidor exige una segunda autorización con credenciales ADMIN. Cuando no
  existe una matriz equivalente se dice explícitamente **sin equivalente de
  matriz**. N3 contiene 69 referencias, no 69 restricciones deduplicadas.
* **X — excluida (16 referencias):** no es una de las tres categorías: son
  notificaciones/audiencia, bypass puro, defaults, invariantes de datos de
  cuenta, flujo de inicio, o visibilidad no sensible. Se conserva para que el
  particionado sea 130/130 y no se infiera un veto.

Los permisos de la matriz (`requierePermiso`, `hasPermission`) se mencionan
solo cuando el guard literal los superpone. Un permiso de matriz no se inventa
cuando la referencia no muestra uno.

## Control de integridad

* El mapa primario contiene una sola aparición de cada ID R001–R130.
* N1+N2+N3+X = 32+13+69+16 = **130**.
* El índice por rol repite IDs deliberadamente para mostrar todos los roles
  afectados; esas incidencias no se suman al conteo.
* Las filas mixtas anotan su cláusula secundaria. En particular, un scope
  territorial no se usa para legitimar un veto de acción; y términos
  financieros, costos o credenciales que bloquean una captura/cancelación
  aparecen como N3 cuando la acción es lo observable, no como simple N2.
