# Contrato E3 UI (preparado, OFF)

## Actualización de integración: catálogo mínimo y folio por sitio

- Usar **`GET /caja/abonos-e3/contexto?buscar=texto&sitioId=2`**, autorizado exclusivamente por `caja_abonos.crear` después del cierre E3 y auth. No usar catálogos globales de clientes/ubicaciones ni ampliar permisos de CAJA. `buscar` opcional máx 100, mínimo dos caracteres para coincidencias, máximo 50. `sitioId` opcional: noADMIN solo sitio asignado, ADMIN puede elegir/consultar activos.
- Respuesta `{ sitios: [{ id, nombre, sesiones: [{ id, ubicacionId, fechaOperativa }] }], clientes: [{ id, nombre, telefono }] }`. Solo tiendas activas y sesiones ABIERTAS no cerradas. Sin saldo, límite ni otros datos financieros. Sin sesión disponible, no habilitar confirmar. Preview/confirm vuelven a validar sesión real.
- Folio final cambió: **`E3-<sitioId>-<consecutivo con mínimo 8 dígitos>`**, por ejemplo `E3-2-00000001`. Namespace contador propio por sitio, patrón transaccional de Entradas/Salidas; NO UUID. `operacionClave` sigue siendo UUID para idempotencia. Usar folio opaco del response sin construirlo en frontend.
- Snapshot ahora exige también **`sitioNombre`, `actorNombre`, `clienteTelefono: string|null`, `clienteRfc: string|null`**, congelados al cobrar. Imprimir nombres legibles, no IDs como sustituto; teléfono/RFC pueden no existir y permanecen null, sin inventarlos.
- Catálogo matriz y seed de permisos E3 fuente OFF; no se agregan módulos operativos ni defaults por un futuro restart no autorizado.
- Preview UUID queda ligado permanentemente a actor + intención (monto/origen/cliente/sitio/medio/etc). Otro actor o cambio de intención exige UUID nuevo; no invalida el preview ajeno. Refresh del mismo actor/intención puede actualizar estado/token.
- Contratos regenerados por instrucción posterior del integrador: codegen final y typecheck libs/API completados, exit 0. Tipos compartidos de contexto y nombres congelados ya disponibles.
- Al liberar E3, los POST legacy `/clientes/:id/pagos` y `/clientes/:id/pagos/vista-previa` rechazan con 409 `E3_DEDICATED_CAPTURE_REQUIRED`: usar las rutas dedicadas nuevas. OFF conserva el flujo legacy. Esto impide evadir `clientes_recapturas` y evita confiar en naturaleza omitida en el preview antiguo.

Base `/api`. Todas las rutas nuevas responden 423 `E3_CLOSED` antes de acceder a DB mientras `E3_ENABLED=false` en backend. Frontend debe usar su propia constante fuente OFF, no env, y no mostrar entradas. No ampliar `clientes_finanzas`. Las vistas previas emitidas se conservan por clave/actor y vencen a los diez minutos: no basta calcular un hash local. No registran dinero.

- `POST /caja/abonos-e3/vista-previa` y `POST /caja/abonos-e3`: permiso matriz `caja_abonos`, crear.
- `POST /clientes/:id/recapturas-e3/vista-previa` y `POST /clientes/:id/recapturas-e3`: permiso `clientes_recapturas`, crear, ADMIN por defecto, configurable para otros usuarios. ClienteId proviene de URL; prohibido Caja.
- JSON común: `{ clienteId, importeCentavos, formaPago: "EFECTIVO"|"TRANSFERENCIA", cuentaDestino: "CAJA_FISICA"|"CUENTA_FISCAL"|"CUENTA_NO_FISCAL", sitioId, sesionCajaId: number|null, operacionClave: UUID, motivo?: string, fechaRecepcion?: ISO8601 }`. Caja requiere sesión abierta incluso transferencia; fecha servidor, no naturaleza enviada. Recaptura exige motivo y fecha histórica con zona, sesionCajaId null. Confirmar añade `previewToken` devuelto por preview. No enviar naturaleza, ticketId o dirigido al flujo FIFO. `asignaciones[].folio` es número nullable, no string. Tipos canónicos E3 en los clientes generados tras codegen; fecha wire es string ISO.
- Preview: `{ previewToken, clienteId, importeCentavos, asignaciones: [{ movimientoVentaId, ticketId, folio, aplicadoCentavos, saldoAntesCentavos, saldoDespuesCentavos }], remanenteCentavos, saldoAFavorCentavos, deudaCentavos, origen: "CAJA"|"RECAPTURA" }`. Token representa estado completo; confirmar revalida bajo candado, 409 `PREVIEW_STALE` obliga preview nuevo.
- Confirmación devuelve `{ recibo: E3Receipt, replay: boolean }`; persistir UUID de intención entre reintentos. Cambiar importe/cliente invalida preview y requiere UUID nuevo. Recibo generado al cobrar, imprimir no cobra. Recaptura genera constancia marcada SIN DINERO NUEVO, no recibo de caja.
- `GET /recibos-e3/:folio`: ADMIN, snapshot inmutable; 404 si ausente, 409 evidencia incompleta, nunca reconstruir.
- `GET /clientes/:id/recibos-e3`: ADMIN lista de snapshots; query opcional `movimientoId` o `sesionCajaId` permite enlaces desde abono/estado/corte. También `GET /caja/recibos-e3?sesionCajaId=...` para corte (ADMIN).
- `POST /recibos-e3/:folio/impresiones`: ADMIN; `{ motivo: string }`; registra solicitud/reimpresión, no afirma impresión física ni altera snapshot; devuelve `{ registrado: true }`.

`E3Receipt`: `{ version:1, folio, movimientoId, clienteId, clienteNombre, clienteTelefono, clienteRfc, sitioNombre, actorNombre, importeCentavos, formaPago, cuentaDestino, sitioId, sesionCajaId, recibidoEn, registradoEn, actorId, origen, motivo, asignaciones, remanenteCentavos, saldoAFavorCentavos, deudaCentavos }`. Dinero entero en centavos; fechas ISO; motivo/teléfono/RFC nullable. Folio propio `E3-<sitioId>-<consecutivo>`. Dos copias A5 horizontal desde otro equipo; no autoimprimir en Caja. Invalidate clientes detail/saldo/pagos/estado-cuenta, Caja sesión/corte tras confirmar; no tras imprimir. En transferencias, `sesionCajaId` del recibo es asociación operativa, nunca imputación a efectivo: el movimiento E1 conserva sesión null y cuenta bancaria.

Dirigido permanece cerrado E5/E7: no ofrecer captura dirigida en este flujo. Política P6 exacta noADMIN se prepara en dominio, nunca simular aplicación pendiente como pagada. Históricos sin snapshot E3 deben explicar falta de evidencia y no usar valores actuales.
